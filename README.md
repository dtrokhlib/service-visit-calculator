# Калькулятор сервісного виїзду

Локальне демо на Vue 3 + TypeScript + Vite. Дві сторінки: `/#/kilometers` та `/#/zones`. Без бекенда, авторизації та бази даних.

## Запуск

Потрібен Node.js 22.12+ (або 20.19+).

```sh
npm install
npm run dev
```

Відкрийте адресу, яку надрукує Vite (зазвичай http://127.0.0.1:5173). Кнопка «Відкрити демоприклад» працює без API-ключа. Умовні відстані в цьому режимі явно позначені на екрані та у звіті; це не результати маршрутизації.

```sh
npm test
npm run build
npm run preview
```

`dist/` можна розмістити на статичному хостингу. Hash-маршрути не потребують серверного перенаправлення. Для розміщення у вкладеній папці задайте `VITE_BASE_PATH=/назва-репозиторію/` перед збіркою; workflow GitHub Pages визначає цей шлях автоматично.

## Geoapify

1. Створіть проєкт і ключ: https://myprojects.geoapify.com/ . Є безкоштовний тариф із квотою; актуальні ліміти: https://www.geoapify.com/pricing/ .
2. Скопіюйте `.env.example` у `.env` та задайте `VITE_GEOAPIFY_API_KEY=ваш_ключ`.
3. Обмежте ключ дозволеними Origins / HTTP referrers: локальна адреса і домен демо. Переконайтеся, що CORS дозволяє ці Origins.
4. Перезапустіть Vite; для хостингу виконайте нову збірку після налаштування змінної.

VITE-ключ є браузерним і потрапляє до збірки, тому обмеження доменів налаштовуються у провайдера. У репозиторій `.env` не потрапляє.

Пошук адрес (від 3 символів із затримкою 400 мс): https://apidocs.geoapify.com/docs/geocoding/address-autocomplete/ . Оберіть конкретну адресу зі списку. Адреси передаються Geoapify для геокодування. За кнопкою «Розрахувати вартість» координати міст та адрес передаються до https://api.geoapify.com/v1/routematrix . Документація: https://apidocs.geoapify.com/docs/route-matrix/ .

Використовується режим `drive`, тип `short`, метричні одиниці. Координати — `[longitude, latitude]`. Відстань з відповіді в метрах перетворюється на кілометри без попереднього округлення. Великі матриці розбиваються на блоки 10 × 10. Зміна моделі використовує отримані відстані повторно. Кожна адреса — незалежний виїзд, а не спільний маршрут. Відсутні маршрути не дають ціни; помилки API не перетворюються на 0 км.

## Тарифи й міста

Редагуйте `public/config.json`; на хостингу це `dist/config.json` (для збереження змін у наступних збірках редагуйте також джерело). Конфіг завантажується при відкритті сторінки без кешування. Для оновлення відкритої вкладки перезавантажте її.

| Поле | Значення / зміст |
| --- | --- |
| `version` | Позначення версії тарифів у звіті |
| `demoCities` | `true`, поки список міст демонстраційний |
| `currency` | `UAH` |
| `perKmGrossUah` | 24 грн за фактичний км з ПДВ |
| `minimumVisitGrossUah` | 10 000 грн, мінімум виїзду з ПДВ |
| `hourlyGrossUah` | 2 226 грн/год з ПДВ |
| `minimumHours` | 3 години на кожен виїзд |
| `zoneWidthKm` | 150 км в один бік |
| `additionalZoneGrossUah` | 5 000 грн з ПДВ за наступну зону |
| `vatRate` | 0.2 (20%, уже включені у тарифи) |
| `cities` | Масив `{ "id": "kyiv", "name": "Київ", "coordinates": [30.5234, 50.4501] }` |

Міста мають мати унікальні `id` і коректні координати. Суми невід’ємні, години та ширина зони додатні. Некоректний конфіг показує помилку замість розрахунку. Налаштувань у формі замовника немає.

Поточні п’ять міст — приклад, не підтверджений список інженерів. Замініть їх фактичними містами/координатами та встановіть `demoCities: false`. У демоприкладі відстані для невідомих міст не вигадуються — маршрут буде позначено як недоступний.

## Формули

`d` — автомобільна відстань в один бік.

- За кілометражем: `виїзд = max(мінімум, d × 2 × ставкаЗаКм)`.
- За зонами: `зона = max(1, ceil(d / ширинаЗони))`; `виїзд = мінімум + (зона − 1) × доплата`. Тут немає додаткового множення на 2.
- Межі: 0–150 км включно — 10 000; понад 150–300 включно — 15 000; понад 300–450 включно — 20 000 грн.
- Робота: `ставкаЗаГодину × мінімальніГодини = 6 678 грн`.
- Разом із ПДВ: `виїзд + робота`.
- ПДВ у складі суми: `разом × vatRate / (1 + vatRate)`.
- Без ПДВ: `разом − ПДВ`.

Мінімальний виїзд із роботою — **16 678 грн із ПДВ**, у тому числі ПДВ **2 779,67 грн**, без ПДВ **13 898,33 грн**. ПДВ вдруге не додається. Грошові складові округлюються до копійок, відстань для визначення ціни не округлюється. На екрані відстань показана з точністю до 1 м.

## PDF

Після розрахунку натисніть «Друк / Зберегти PDF» і виберіть «Зберегти як PDF» у системному діалозі. Друкується поточна модель, дата, версія, формули та таблиці всіх порахованих адрес. Формат — A4 альбомний; заголовки таблиць повторюються, елементи керування приховані. За потреби вимкніть стандартні колонтитули браузера.

Суми альтернативних міст не додаються. Звіт не є офертою, не підтверджує доступність інженерів і не прогнозує час приїзду. Введені адреси й результати зберігаються лише в пам’яті вкладки та очищаються після перезавантаження. Дані залишаються при переході між калькуляторами.

## Перевірки

Vitest перевіряє мінімум і поріг кілометрового тарифу, межі зон, включений ПДВ, зміни конфігурації, недопустимі дані, монотонність вартості, порядок осей маршрутної матриці, відсутні маршрути, блоки великих запитів, помилки квоти та результати геокодування. `npm run build` також перевіряє TypeScript і Vue-шаблони.

### Стан перевірки

30 тестів, `npm run check:public` та повна команда `npm run build` із перевіркою Vue-типів пройшли. Браузерна перевірка і фактичне збереження PDF залишаються ручними перевірками. Реальні запити Geoapify потребують ключа; тести адаптера використовують підготовлені відповіді.

Ручний контроль після встановлення: відкрийте демоприклад → перевірте 2 адреси × 5 міст → перейдіть на іншу модель і переконайтеся, що адреси збереглися → збережіть PDF → перевірте мобільний вигляд і перенесення довгої таблиці. Далі з API-ключем додайте реальну адресу зі списку, розрахуйте маршрути, змініть адресу і перевірте скидання старого результату.

## Публічний репозиторій і CI/CD

Для цього статичного демо рекомендовано **GitHub Pages + GitHub Actions**: один сервіс для коду, тестів і хостингу. GitHub Pages доступний для public-репозиторіїв на GitHub Free: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages .

У `.github/workflows/pages.yml` уже підготовлено:

- Для PR і push у `main`: `npm ci` → перевірка публічних файлів → тести → повна збірка без ключів.
- Після успішних перевірок у `main`: окрема збірка із ключем із GitHub Secrets → публікація лише `dist/` у Pages.
- PR не отримує ключа. Для деплою використовується автоматичний GitHub token та OIDC, особистий PAT не потрібний. Actions зафіксовані на конкретних commit SHA.
- `base` визначається з налаштувань Pages: працює і шлях `/repository/`, і кореневий домен.
- Lock-файл містить платформні пакети для Linux CI та macOS.

Одноразове налаштування після створення репозиторію:

1. Запуште проєкт із `package-lock.json` і `.github/workflows/pages.yml` у гілку `main`.
2. У **Settings → Pages → Build and deployment → Source** виберіть **GitHub Actions**.
3. У **Settings → Secrets and variables → Actions → New repository secret** додайте `VITE_GEOAPIFY_API_KEY`. Без цього секрету буде опубліковано демо без реального пошуку адрес.
4. У Geoapify дозвольте Origin `https://<username>.github.io` та HTTP referrer вашого сайту `https://<username>.github.io/<repository>/*`. Для власного домену вкажіть його. Для localhost зручніше окремий ключ.
5. Запустіть workflow вручну у вкладці Actions або запуште наступну зміну в `main`.
6. Для `main` увімкніть branch protection / ruleset: PR перед merge та успішний check **Public files, tests and build**.

Налаштування Pages та GitHub Secrets виконується в обліковому записі власника. Сам репозиторій і сайт цими локальними змінами ще не створені й не опубліковані.

Альтернатива — **Cloudflare Pages**, якщо потрібні окремі preview-адреси для гілок: підключіть GitHub-репозиторій, production-гілка `main`, build command `npm test && npm run build`, output directory `dist`, Node.js 22, `VITE_BASE_PATH=/`, ключ через змінні середовища хостингу. Не використовуйте одночасно Pages-деплой із цього workflow; залиште тільки job `check`. Документація: https://developers.cloudflare.com/pages/get-started/git-integration/ .

### Що залишається приватним

`.gitignore` виключає локальні `.env*` (крім порожнього `.env.example`), `node_modules/`, `dist/`, внутрішній документ `service_visit_codex_context.md`, ключові файли та локальні журнали. Локальний `.env` збережено для роботи застосунку; його вміст не потрібно додавати до Git. Внутрішній документ збережено локально, він не потрібен для збірки.

Перед першим комітом:

```sh
npm run check:public
```

Перевірка включає вже відстежувані Git файли навіть тоді, коли вони додані в `.gitignore`, і завершується помилкою при знаходженні приватних файлів або відомих форматів ключів. Знайдені значення не друкуються. Це базова перевірка, а не повний сканер секретів; перегляньте склад першого коміту. До створення Git-репозиторію перевіряються файли проєкту з урахуванням локальних виключень.

**GitHub Secrets не приховує браузерний ключ від відвідувача сайту.** Vite вбудовує `VITE_GEOAPIFY_API_KEY` в JavaScript під час збірки. Репозиторій не містить значення ключа, але у відданому браузеру коді воно доступне. Для такого демо використовуйте окремий обмежений за доменом ключ Geoapify, а не універсальний серверний секрет. Якщо ключ мусить бути повністю прихованим, потрібен серверний проксі — це вже інша архітектура. Налаштування обмежень: https://myprojects.geoapify.com/help/api-keys/ .

`public/config.json` доступний відвідувачам. У репозиторії залишені демонстраційні міста та тарифи; не додавайте сюди персональні дані інженерів, приватні домашні адреси або конфіденційні тарифи.
